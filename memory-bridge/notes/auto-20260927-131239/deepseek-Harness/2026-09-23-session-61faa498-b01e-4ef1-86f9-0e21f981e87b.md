### 诊断移动固态硬盘热插拔后掉速问题，产出只读健康诊断脚本

**问**：长时间传输过程中热插拔移动固态硬盘后严重掉速，怎么办。

**做**：解读用户提供的 ATTO 与 AS SSD 两张跑分图（ATTO 顺序读写 954/1021 MB/s，AS SSD Seq 963/910、4K 24.02/66.26、4K-64Thrd 227.69/265.55、总分 348/423/954），判断瓶颈在 4K 随机而非顺序；分析热插拔可能造成的损伤（FTL 映射表损坏、半编程坏块、只读降级、链路降级、USB 桥异常、空间不足）；编写只读诊断脚本 `tools\ssd-health-probe.ps1` 并做 PowerShell 语法检查；给出 6 步修复阶梯。

**结论/决定**：
- 盘大概率没坏：顺序读写跑满 SATA 6Gb/s + USB 10Gbps/UASP 上限，写入仍达 910 MB/s 说明未进只读模式，链路未降级。
- 弱项集中在 4K 随机（读 24 < 写 66）和高队列深度，符合 DRAM-less 主控（SM2258XT/2259XT 一类）+ FTL 频繁回读 NAND 的特征；联想 K122 为 OEM 盘，大概率此方案。
- ATTO 每档仅 256MB，测的是 SLC 缓存前段最好成绩，与热插拔当天持续写入超缓存后的真实速度不是一回事。
- 最可能原因是"DRAM-less 盘 + 缓存耗尽 + 空间太满"叠加，热插拔只是把脆弱状态推到台前。
- 修复顺序：备份校验 → 冷复位/直连 SATA 对比（区分盘与盒子问题）→ 带电空置 2–6 小时自愈 → 全盘 TRIM → 清到留 20–30% 空闲 → Secure Erase（非格式化）→ 仍差则走保修。
- 强调：写入中拔盘存在静默数据损坏风险，任何修复/格式化前先备份并用 `certutil -hashfile <文件> SHA256` 抽检。

- 手机传输慢的原因排序：① 数据线是充电线或损坏，链路回落到 USB 1.1（12 Mbps≈1.5 MB/s，低速 1.5 Mbps≈200 KB/s，与"几 KB"量级吻合，最可能）；② 接口协商到 USB 2.0（上限约 35–40 MB/s，解释不了"几 KB"）；③ MTP 协议 + 大量小文件（每文件往返协商，1–8 MB/s 属正常）；④ 手机侧存储慢（SD 卡 10–30 MB/s）。

- 若确认是小文件+MTP：改用局域网 FTP/SMB（千兆可到 100+ MB/s）或 `adb push`，避免用 MTP 传几千个小文件。
