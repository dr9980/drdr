# web — 2026-09-18

### 诊断并修复 dsh-agent-teams 插件安装失败：改用 npm 预构建包 + git URL 重写

**问**：插件 `https://github.com/NanmiCoder/dsh-agent-teams/` 安装失败（`Host key verification failed` / `git fetch --depth 1` exit 128），要求诊断并修复后报告结果。

**做**：
- 定位到两个叠加缺陷：
  1. `github:` 简写让 pnpm 用 git 解析 ref，走 SSH；本机无 `known_hosts`、无 SSH 密钥 → 主机密钥校验失败。用对照实验坐实：无重写时 `git fetch --depth 1 origin e22bd19...` 报 `Host key verification failed`（与用户报错逐字一致），加重写后成功。
  2. 改走 HTTPS 后安装"成功"但插件不可用：GitHub tarball 是源码快照，无 `lib/`；该包只有 `prepublishOnly`、无 `prepare`，lockfile 无 `requiresBuild`，pnpm 不执行构建。而 DSH 的 `reconcilePlugins` 只检查包是否声明 `dsh.bundle.patch`，不检查构建产物。
- 修复：在 `C:\Users\AAA\.gitconfig` 写入 `[url "https://github.com/"] insteadOf = git@github.com:` 和 `insteadOf = ssh://git@github.com/`；移除 git 来源的残缺安装；执行 `dsh plugin --profile web add @nanmicoder/dsh-agent-teams@^0.1.20`。
- 验证：`lib/index.js`、`lib/client.js`、`cordis.patch.yml` 全部就位；依赖登记进 `dsh.profile.bundles`；`@deepseek-ai/*` 从插件位置解析到宿主 0.1.5-rc.2；`dsh --profile web --dump-config` 退出码 0、668 行、61 条 patch 无 id 冲突；客户端 bundle 为自包含单文件（197KB、零外部 import）。

**结论/决定**：
- 改用 npm 官方发布版而非 git 源，因为 `@nanmicoder/dsh-agent-teams@0.1.20` 在 npm 上带完整构建产物，且版本号与 git HEAD 完全相同，git 路线根本走不通。
- git URL 重写设为用户级（`~/.gitconfig`），可逆、公开仓库无需 SSH 密钥，一劳永逸解决后续 GitHub 插件安装。
- 未重启 DSH web 服务器（会中断当前会话），插件需重启后生效。
