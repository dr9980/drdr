# web — 2026-09-18

### 修复 dsh 插件安装失败：根因是 git+ssh URL 重写缺失 + github.com 直连不通，非目标插件本身

**问**：安装 `https://github.com/NanmiCoder/dsh-agent-teams.git` 到 profile `web` 时报 `Host key verification failed` / `git fetch exit 128`，要求诊断并修复后重装。

**做**：
- 定位报错 commit `e22bd19af7d27e0f7302061808d0cbd7dc9b0914` 实际属于 `@deepseek-ai/dsh-security-audit`（走 `github:omdsh-dev/...`），而目标插件 `@nanmicoder/dsh-agent-teams` 走 npm registry（`0.1.20`）；前者失败导致整批 install 回滚。
- 连通性实测：`github.com:443` 直连超时；`codeload.github.com`、`api.github.com`、`registry.npmjs.org` 通；本机代理 `127.0.0.1:7897` 可用但 git 不读 Windows 系统代理。
- 检查 `~/.gitconfig`：原有 `insteadOf` 只覆盖 `git@github.com:` 和 `ssh://git@github.com/`，**缺 `git+ssh://git@github.com/`**（pnpm 展开 `github:` 用的正是这个形式）；且 `C:\Users\AAA\.ssh` 目录不存在，必然 host key 校验失败。
- 修改 `C:\Users\AAA\.gitconfig`：新增 `insteadOf = git+ssh://git@github.com/`，并加 `[http "https://github.com/"] proxy = http://127.0.0.1:7897`；原文件备份为 `C:\Users\AAA\.gitconfig.bak-20260918-215327`。
- 未改动 `package.json` / `pnpm-lock.yaml` / `pnpm-workspace.yaml`（快照备份在 `C:\Users\AAA\.dsh\profile-backups\web-20260918-215348\`）。
- 验证：原失败命令 `git -c core.longpaths=true fetch --depth 1 origin e22bd19...` → exit 0；干净临时目录 `pnpm add github:omdsh-dev/dsh-security-audit#e22bd19...` → exit 0；profile `pnpm install` → exit 0 且幂等；7 个依赖齐全含 `@nanmicoder/dsh-agent-teams@0.1.20`；`agent_teams_status` 正常响应证明插件已运行时加载。

**结论/决定**：
- 目标插件本身没问题，是兄弟依赖 `dsh-security-audit` 的 git 拉取失败拖垮整批安装。
- 修复选择改 `~/.gitconfig`（补 URL 重写 + 给 github.com 配代理），而非改依赖形式或装 SSH 密钥——因为 `codeload.github.com` 直连可用、代理已在本机运行，改动面最小。
- 不建议把 agent-teams 改成跟踪 GitHub 仓库（会引入每次安装都需 git 的依赖）。
- dsh 提示的 "add the exact key under allowBuilds" 是**误报**：`dsh/lib/plugin-Ddi42qoW.js:125` 只要参数含 `github:`/`.git` 就无条件打印，pnpm 从未输出该键，且 `dsh-security-audit` 无 `prepare` 脚本。
