- 核查 DSH web seam 的 provider 选择规则：`searchProvider`/`fetchProvider` 为单选、无优先级链；未配置 id 且仅有一个可用 provider 时自动选中。

**结论/决定**：
- **推荐方案 A：不装**。理由：用户当前已有官方搜索通道，装插件是把第一方通道换成第三方（Firecrawl 免注册每月 1000 credits 上限），收益不抵替换成本。
- 若确需 X 搜索，推荐**方案 B**：装插件但在用户层 `cordis.patch.yml` 把 `web` 行的 `searchProvider` 钉回 `deepseek-official`，只取 `x_search` + `read_page` 两个新工具。作者注释明确支持 "a later profile patch can pin any provider back"。
- 方案 C（全量装）仅适合常搜 X 或官方搜索常被限流的场景。
- 澄清宣传语"DeepSeek 模型自身不能联网"**不适用于本环境**——DSH 已接好官方搜索。
- 已排除的担忧：patch 会丢掉 `fetchProvider: http`，但因插件不注册 fetch provider，仅剩 `dsh-web-fetch-http` 一个可用 provider 会被自动选中，`web_fetch` **不会坏**；如需稳妥可在同条 patch 写回 `fetchProvider: http`。

**产出**：无文件产出（纯评估与建议，等待用户选择方案后再动手）。
