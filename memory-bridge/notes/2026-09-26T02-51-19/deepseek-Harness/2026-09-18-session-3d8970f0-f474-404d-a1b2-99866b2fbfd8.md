### 评估 @liustack/modsearch 插件：结论为不建议安装，除非明确需要 X 搜索

**问**：这个插件怎么样，我需要安装吗？

**做**：
- 实测当前会话的 `web_search` 可用，确认现有配置为 `searchProvider: deepseek-official` + `fetchProvider: http`，由 `@deepseek-ai/dsh-web-search-deepseek`（用用户自己的 DEEPSEEK_API_KEY）和 `@deepseek-ai/dsh-web-fetch-http` 支撑。
- 拉取并解码插件的 `cordis.patch.yml`、`package.json`、`dsh/index.js` 源码，确认其行为。
- 用 pwsh 实测三个默认搜索后端在本机可达性：firecrawl 200 / tavily 405 / exa 404（均为正常响应）。
- 核对 Node 版本要求（插件 `>=22.13`，本机 v24.21 ✓）。

**结论/决定**：
- **不建议安装（方案 A）**。理由：DSH 的 web seam 是**单选**的，`searchProvider` 只能指向一个 provider，装 ModSearch 是**替换**官方搜索通道（`deepseek-official` → `modsearch`），而非"新增联网能力"。宣传语"DeepSeek 模型自身不能联网"不适用于本环境。
- 插件真正新增的能力只有两项：`x_search`（搜 X/推特，官方做不到）和 `read_page`（经模型加工的单页阅读：摘要+正文抽取+外链+不确定项+告警）。
- 若只想要这两个新工具，可用**方案 B**：在用户层 `cordis.patch.yml` 里把 `web` 行的 `searchProvider` 钉回 `deepseek-official`（插件作者注释明确支持 "a later profile patch can pin any provider back"）。
- 项目体检良好：498 star、MIT、活跃维护（3 天前有提交）、运行时依赖仅 `commander` + `undici`、源码有防原型污染/拒绝符号链接/0600 权限+原子改名/请求体 64KiB 上限/密钥不回传浏览器等克制设计。
- 两个必须告知的风险：① Firecrawl 免注册通道每月仅 1,000 credits，官方通道无此月度上限；② `/modsearch/config` 路由不继承 DSH Connection 鉴权、不施加 Host/Origin/Fetch Metadata 策略——**仅在保持免密钥状态时基本无害**，一旦填入 Tavily/Exa/Firecrawl 的 API Key，恶意网页理论上可 POST 该路由篡改 `baseURL` 从而窃取密钥。
- 已澄清一个潜在副作用：patch 会整体替换 `web` 行 config 从而丢掉 `fetchProvider: http`，但 ModSearch **只注册 search provider、不注册 fetch provider**，fetch 侧仍只剩 `dsh-web-fetch-http` 一个可用 provider，按选择规则会自动选中，**`web_fetch` 不会坏**。

**产出**：无文件产出（纯评估回合）。参考链接：https://github.com/liustack/modsearch 、https://www.npmjs.com/package/@liustack/modsearch

**要点**：
- 插件版本 `@liustack/modsearch@5.10.3`，作者 Leon Liu（liustack），与已安装的 `modlens` 同一作者。
- 其 `cordis.patch.yml` 内容为：`- id: web` / `config: searchProvider: modsearch`，外加 `insert: - id: modsearch / name: '@liustack/modsearch'`。
- 插件通过 `registerSearchProvider({id:'modsearch', available:()=>true})` 注册，`search()` 会 spawn 打包的 CLI（`dist/main.js`），参数形如 `-q <query> --source web --timeout 55000`。
- 插件还附带一个 agent skill（`skills/modsearch/SKILL.md` + scripts + references）和一个 CLI bin。
- 若走方案 B，建议在同一条 patch 里把 `fetchProvider: http` 一并写回以求稳妥。
- 用户约定：安装类操作**装完不重启**，装前先跑 `dsh-security-audit` 扫插件，装完回报结果与验证。
