- **git 源仍然装不成**，仓库至今未修：装出的目录只有 `assets/`、`release-notes/`、`scripts/` 和配置文件，**没有 `lib/`、没有 `lib/index.js`**；而 `package.json` 的 `main` 指向 `lib/index.js`；`scripts.prepare` 不存在（只有 `prepublishOnly`，git 安装不触发）。这正是此前 `Cannot find module ...\lib\index.js` 报错和"profile 未新增任何依赖"的成因。
- **决定：不要用该 git URL 再装**，否则会把可用的 registry 版覆盖成坏的空壳。现有安装形态正确：npm registry 的 `@nanmicoder/dsh-agent-teams@0.1.20`（git 源 HEAD 版本号同为 0.1.20，功能无损失）。
- 使用方式：在 web 会话或终端 TUI 里说"用 AgentTeams 做 XXX"，流程为**先出计划（成员 + 任务依赖图）并停下等用户点「批准并运行」**，不会自动开工。

**产出**：无持久文件（临时目录已清理，两个 profile 未被改动）。

**要点**：
- 版本号：registry 与 git 源 HEAD 均为 `0.1.20`。
- 判定 git 源不可用的关键证据：缺 `lib/` 目录 + `main` 指向不存在的 `lib/index.js` + 无 `prepare` 脚本。
- 安装命令报"成功"不等于可用——pnpm 对 git 源会报 `Packages: +1` 但产物是空壳。
