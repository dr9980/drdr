# web — 2026-09-18

### 诊断并修复 dsh-agent-teams 插件安装失败：改用 npm 预构建包 + 持久化 git HTTPS 路由

**问**：插件 `https://github.com/NanmiCoder/dsh-agent-teams/` 安装失败（`Host key verification failed` / `git fetch --depth 1` exit 128），要求诊断并修复后重装。

**做**：
- 定位到失败是**两个独立缺陷叠加**：
  1. `github:` 简写让 pnpm 用 git 解析 ref，`git@github.com:` 走 SSH；该机器无 `known_hosts`、无 SSH 密钥 → 主机密钥校验失败。
  2. 改用 HTTPS 后安装"成功"，但 GitHub tarball 是**源码快照**：无 `lib/`，包只有 `prepublishOnly`、**无 `prepare`**，lockfile 无 `requiresBuild` → pnpm 不构建，`main`/`exports` 指向的 `lib/index.js` 永远不存在。
- 修复：在 `C:\Users\AAA\.gitconfig` 写入 `[url "https://github.com/"] insteadOf = git@github.com:` 和 `insteadOf = ssh://git@github.com/`；移除残缺 git 安装；执行 `dsh plugin --profile web add @nanmicoder/dsh-agent-teams@^0.1.20`。
- 验证：`lib/index.js`、`lib/client.js`、`cordis.patch.yml` 就位；已登记进 `dsh.profile.bundles`；`@deepseek-ai/*` 从插件位置解析到宿主 0.1.5-rc.2；`dsh --profile web --dump-config` 退出码 0、668 行、61 条 patch 无 id 冲突；客户端 bundle 为自包含单文件（197KB、零外部 import）。

**结论/决定**：
- 选择 npm 官方发布版而非 git 来源，因为 `@nanmicoder/dsh-agent-teams@0.1.20` 在 npm 上带完整构建产物，且版本号与 git HEAD 完全相同；git 路线根本走不通（无 `prepare` 脚本，`allowBuilds` 建议对该包无效）。
- 用 `.gitconfig` 的 `insteadOf` 做持久修复（用户级、公开仓库无需密钥、易回滚），而非临时改单次命令。
- 未重启 DSH web 服务器，避免中断当前会话；插件需重启后生效。
